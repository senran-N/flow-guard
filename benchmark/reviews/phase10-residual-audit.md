# Phase 10 residual-diagnostic audit (2026-11-12)

## Scope and method

This is a bounded, read-only audit of **12 representative phase9 diagnostics**, not a rescan and not an accuracy measurement. The frozen run was `benchmark/results/2026-11-12-phase9` (`bruno.1.json` and `ripgrep.1.json`); source evidence below was independently checked in `D:/Myproject/crack` at the corpus revision. No source, original repository, manifest, or test configuration was changed.

Phase9 reports 350 `VIOLATED` + 94 `INCONCLUSIVE` obligations for Bruno and 65 `VIOLATED` + 5 `INCONCLUSIVE` obligations for ripgrep. A count decrease/increase is not treated as an accuracy result. The sample is deliberately concentrated on the two largest residual clusters and cannot establish a global false-positive rate or that any repository is clean.

Legend: **FP** means the specific `VIOLATED` conclusion conflicts with independently found in-tree wiring; **pending** means the static evidence does not justify `VIOLATED`, but does not prove the API is live. “Original alert” is quoted/paraphrased faithfully from the stored JSON finding (all twelve use the same Chinese `unwired export` wording unless noted).

## Root-cause consolidation

1. **JSX/default-export and framework lifecycle edges (Bruno):** a normal default-import/default-export component edge and JSX instantiation are lost, then each reachable `React.Component` lifecycle method is independently misclassified as an exported application function. Four lifecycle alerts in one class are derivative duplicates. This explains the sampled false positives and plausibly a material portion of the 350; it does **not** establish that all 350 share this cause.
2. **Rust visibility is being mistaken for application entry obligation:** `pub(crate)` modules, `pub use … as …`, external-looking workspace crate names (for example `grep::cli`), and receiver calls after re-export do not resolve to their definitions. `pub` APIs of a workspace library are additionally mislabeled as application features despite valid out-of-workspace callers.
3. **Generated/dispatch functionality:** shell-completion/help generators are intentionally selected through enum modes. A graph that only rewards direct spellings cannot see `GenerateMode → main::{generate,special} → alias → implementation`.

## Rust cfg, macros, and Cargo target boundary

The audited ripgrep source contains target semantics beyond what phase9 can safely prove:

- `crates/cli/src/lib.rs:173,218,243` selects Unix, Windows, and fallback implementations with `#[cfg(...)]`; `crates/cli/Cargo.toml:22,25` supplies the corresponding target-specific dependencies.
- Root `Cargo.toml:66` adds `tikv-jemallocator` only for `all(target_env = "musl", target_pointer_width = "64")`. `.cargo/config.toml` has named Windows-MSVC and `x86_64-unknown-linux-musl` target rustflags.
- `crates/core/flags/doc/version.rs:56-154` has feature (`pcre2`) and architecture/target-feature branches, and the doc modules define local `macro_rules! write`/`writeln` wrappers (`doc/help.rs:19`, `doc/man.rs:14,21`).

`src/conditional-context.mjs` attaches declaration-level `#[cfg]` text and only proves a small set of mutual exclusions; `src/rust-imports.mjs` has no Cargo-metadata, feature-resolution, macro-expansion, build-script, or selected-target model. Therefore a phase9 connectivity result must not assert absence/presence for a non-host target, feature-gated path, procedural/declarative macro-generated item, or Cargo-selected dependency. This audit found no basis to convert that limitation into a defect claim.

## High-yield, implementable remediation

1. **React graph pass before entry obligations:** record `export default` bindings, resolve default/aliased imports with configured path aliases, and create component edges for uppercase JSX tags. For a class extending `React.Component` (including imported aliases), add synthetic framework edges from its reachable component node to `constructor`, `componentDidMount`, `componentDidUpdate`, and `componentWillUnmount`; mark uncertain inheritance as `INCONCLUSIVE`, never `VIOLATED`. Deduplicate member findings under the parent component.
2. **Rust workspace-aware resolver:** parse workspace/package `Cargo.toml` package names and path dependencies, map `grep::cli` to the local package crate root, and resolve `pub use` aliases/re-export chains across crate roots. Carry receiver origin/type through simple chains (`builder.get_matcher().has_command`) before issuing no-caller diagnostics.
3. **Obligation policy by visibility/package role:** only enforce application-entry wiring for executable/package entry targets or an explicit blueprint. Treat `pub` library APIs without a caller as `INCONCLUSIVE` (or reserve), and treat `pub(crate)` as internal reachability candidates after Rust resolution—not automatically as UI/application exports.
4. **Target-aware uncertainty first:** ingest Cargo target dependency sections and `.cargo/config.toml` target names into a target/feature context. Until compilation-aware cfg/macro expansion exists, downgrade findings whose sole evidence/caller lies behind unresolved `cfg`, feature, or macro expansion; do not fabricate cross-target edges. A focused regression fixture should cover (a) `pub use … as` + enum dispatch, (b) a workspace package rename, (c) a method chain, and (d) mutually exclusive Unix/Windows items.

No claim is made that these changes reduce all residual diagnostics, preserve recall, or make the tool suitable as a general production gate. They need targeted regressions plus the existing corpus/holdout reruns, with diagnostics and blocking outcomes reported separately.
